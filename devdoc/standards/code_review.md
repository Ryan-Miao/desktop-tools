# 代码评审检查清单 (Code Review Checklist)

## 概述

本检查清单用于Pull Request评审，确保代码质量和项目标准的一致性。

**使用说明**:

- 评审者使用此清单检查PR
- 勾选所有适用项目
- 对于不合格项，在PR评论中指出
- Critical/Major变更需要额外检查

---

## 自动化检查（CI）

CI会自动运行以下检查，必须在PR中通过：

### 代码质量

- [ ] **Lint检查通过** (`npm run lint`)
  - 无ESLint错误
  - 代码风格一致

- [ ] **类型检查通过** (`npm run type-check`)
  - 无TypeScript类型错误
  - 无`any`类型（除非合理）

- [ ] **所有测试通过** (`npm test`)
  - 单元测试通过
  - 集成测试通过
  - 无测试超时

### 测试覆盖率

- [ ] **覆盖率阈值达标** (`npm run test:coverage`)
  - 核心代码 >= 80%
  - UI组件 >= 60%
  - 工具函数 >= 80%

- [ ] **核心代码验证通过** (`npm run test:verify-coverage`)
  - 核心代码满足严格阈值

### E2E测试

- [ ] **E2E测试通过** (`npm run test:e2e`)
  - 关键用户流程测试通过
  - 无E2E测试失败

### 控制台错误

- [ ] **无控制台错误**
  - 开发者控制台无红色错误
  - 无警告（除非已知）

## 通用检查（所有变更）

### 代码质量

- [ ] **代码清晰易懂**
  - 变量和函数命名清晰
  - 复杂逻辑有注释
  - 避免过度嵌套

- [ ] **无重复代码**
  - 提取公共函数
  - 复用现有工具

- [ ] **性能考虑**
  - 无明显性能问题
  - 无内存泄漏
  - 大数据集优化

- [ ] **错误处理**
  - 所有async函数处理错误
  - 适当的错误类型
  - 用户友好的错误消息

### 测试

- [ ] **测试充分**
  - 新功能有测试
  - 边界条件测试
  - 错误场景测试

- [ ] **测试质量**
  - 测试命名清晰
  - 遵循AAA模式
  - 无脆弱测试

### 文档

- [ ] **代码文档**
  - 公共API有JSDoc
  - 复杂算法有注释
  - 使用示例

- [ ] **更新文档**
  - README更新（如需要）
  - API文档更新
  - CHANGELOG更新（用户可见变更）

### Commit信息

- [ ] **Conventional Commits格式**
  - 正确的类型（feat/fix/docs/refactor等）
  - 清晰的描述
  - 相关issue编号

---

## Critical变更额外检查

对于**Critical变更**，除通用检查外，还需：

### 设计文档

- [ ] **设计文档已创建**
  - 链接到设计文档
  - 文档完整
  - 包含影响分析

- [ ] **设计已批准**
  - 技术lead批准
  - 设计评审通过

### 测试

- [ ] **80%覆盖率达标**
  - 行覆盖率 >= 80%
  - 分支覆盖率 >= 70%
  - 所有关键路径覆盖

- [ ] **性能测试**
  - 启动时间测量
  - 内存使用检查
  - CPU使用分析

- [ ] **E2E测试**
  - 关键流程覆盖
  - 错误恢复测试
  - 数据持久化测试

### 破坏性变更

- [ ] **迁移路径**
  - 迁移脚本存在
  - 自动迁移（如可能）
  - 回退行为定义

- [ ] **弃用政策**
  - 旧API标记@deprecated
  - 迁移示例提供
  - 移除时间表明确

- [ ] **BREAKING_CHANGES.md**
  - 更新破坏性变更文档
  - 迁移指南完整
  - 影响范围清晰

---

## Major变更额外检查

对于**Major变更**，除通用检查外，还需：

### 设计文档

- [ ] **设计文档已创建**
  - 功能说明清晰
  - 技术方案合理
  - 影响评估完整

- [ ] **设计已批准**
  - 功能评审通过
  - 技术可行性确认

### 测试

- [ ] **70%覆盖率达标**
  - 行覆盖率 >= 70%
  - 集成测试充分

- [ ] **新功能测试**
  - 主要场景覆盖
  - 用户交互测试
  - 边界条件测试

### 文档

- [ ] **用户文档**
  - 功能说明
  - 使用示例
  - 截图/视频（复杂功能）

- [ ] **API文档**
  - 公共接口文档
  - 类型定义导出
  - 使用示例

---

## Minor变更检查

对于**Minor变更**，需检查：

### Bug修复

- [ ] **复现测试**
  - 有失败测试重现bug
  - 修复后测试通过

- [ ] **根本原因**
  - 理解根本原因
  - 修复正确位置
  - 添加相关测试

### 小增强

- [ ] **边界条件**
  - 考虑边界情况
  - 添加相应测试

- [ ] **向后兼容**
  - 不破坏现有功能
  - 保持API兼容

---

## Trivial变更检查

对于**Trivial变更**，需检查：

- [ ] **现有测试通过**
  - 不破坏现有测试
  - 功能正常工作

- [ ] **文档一致性**
  - 文档与代码一致
  - 更新相关文档

## 特定类型检查

### React组件

- [ ] **组件结构**
  - Props类型定义
  - 默认Props值
  - 合理的组件拆分

- [ ] **性能**
  - 避免不必要的re-render
  - React.memo适当使用
  - useCallback/useMemo正确使用

- [ ] **状态管理**
  - useState/useContext正确使用
  - 状态提升合理
  - 避免prop drilling（如需要）

- [ ] **可访问性**
  - 键盘导航支持
  - ARIA标签
  - 焦点管理

### TypeScript

- [ ] **类型安全**
  - 无`any`类型
  - 使用`unknown`代替
  - 泛型使用合理

- [ ] **类型定义**
  - Interface/Type选择合理
  - 导出公共类型
  - 避免类型断言

- [ ] **严格模式**
  - strictNullChecks
  - noImplicitAny
  - noUnusedLocals

### 异步代码

- [ ] **Promise处理**
  - 正确使用async/await
  - 错误处理（try/catch）
  - 避免Promise.reject

- [ ] **竞态条件**
  - 取消旧请求
  - 加载状态管理
  - 错误边界

### 状态管理（Zustand）

- [ ] **Store设计**
  - 合理的状态切片
  - actions和selectors分离
  - 避免嵌套过深

- [ ] **性能**
  - 选择器优化
  - 避免不必要的订阅

### 数据库操作

- [ ] **SQL安全**
  - 使用参数化查询
  - 避免SQL注入
  - 事务使用正确

- [ ] **性能**
  - 索引使用
  - 查询优化
  - 连接池管理

### IPC通信

- [ ] **类型安全**
  - IPC channel类型定义
  - 参数验证
  - 错误处理

- [ ] **安全**
  - 验证来源
  - 限制敏感操作
  - 错误不暴露信息

**批准** ✅

- 所有检查通过

**需修改** ⚠️

- 有minor问题
- 需要澄清
- 建议改进

**拒绝** ❌

## 快速参考

### Critical/Major变更流程

1. 检查设计文档存在并已批准
2. 验证覆盖率达标
3. 检查性能和E2E测试
4. 确认迁移路径（如破坏性）
5. 验证文档完整

### Minor/Trivial变更流程

1. 检查现有测试通过
2. 验证代码质量
3. 确认文档更新（如需）
4. 检查向后兼容

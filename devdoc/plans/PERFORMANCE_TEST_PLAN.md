# Day 2.5: 异步日志写入性能测试

## 测试目标
验证统一日志框架的异步写入不会阻塞UI线程

## 测试原理
- 日志写入通过IPC发送到主进程
- 主进程异步写入日志文件
- 渲染进程不应该被阻塞
- UI应该保持流畅响应

## 测试环境
- **桌面模式**: `npm run dev` (推荐，可以测试文件写入)
- **Web模式**: `npm run dev:web` (仅测试控制台输出)

## 测试方法
在浏览器开发者工具控制台中执行性能测试函数

## 测试步骤

### 步骤1: 启动应用并打开控制台
1. 启动应用: `npm run dev`
2. 打开浏览器开发者工具 (F12)
3. 切换到 Console 标签
4. 等待应用加载完成

### 步骤2: 基础性能测试 (1000条日志)
在控制台执行:
```javascript
testLogPerformance(1000)
```

**预期结果**:
- 总耗时应该在 100-500ms 之间
- 平均每条日志 < 0.5ms
- UI 没有卡顿（可以移动鼠标、滚动页面）
- 测试完成后显示性能统计

**成功标准**:
- ✅ 总耗时 < 1000ms
- ✅ UI 保持响应（鼠标移动流畅）
- ✅ 没有错误消息

### 步骤3: 压力测试 (10000条日志)
在控制台执行:
```javascript
testLogPerformance(10000)
```

**预期结果**:
- 总耗时应该在 1-3 秒之间
- 平均每条日志 < 0.3ms
- UI 可能轻微延迟，但不会完全冻结

**成功标准**:
- ✅ 总耗时 < 5000ms
- ✅ UI 最终恢复响应
- ✅ 没有内存泄漏警告

### 步骤4: UI响应性测试
在执行性能测试的同时，尝试以下操作:

1. 在控制台执行:
```javascript
// 启动连续测试
setInterval(() => {
  console.log('[UI测试] 页面仍然响应');
}, 500);
```

2. 立即执行性能测试:
```javascript
testLogPerformance(5000)
```

**预期结果**:
- 在日志写入过程中，应该看到 `[UI测试]` 消息持续输出
- 这证明主线程没有被完全阻塞

### 步骤5: 内存使用测试 (Chrome/Edge)
在控制台执行:
```javascript
// 保存结果以检查内存
const result1 = await testLogPerformance(1000);
console.log('内存使用:', result1.memoryUsed, 'MB');

// 等待垃圾回收
await new Promise(resolve => setTimeout(resolve, 2000));

// 再次测试
const result2 = await testLogPerformance(1000);
console.log('第二次内存使用:', result2.memoryUsed, 'MB');
```

**预期结果**:
- 两次测试的内存使用应该相近
- 没有明显的内存增长

## 故障排查

### 问题1: UI 冻结或卡顿
**原因**: 日志写入阻塞了主线程
**检查**:
- 确认日志使用 IPC 异步发送（`ipcRenderer.send` 不是 `invoke`）
- 确认主进程日志写入是异步的（使用 `async/await`）

### 问题2: 内存使用持续增长
**原因**: 日志条目没有被正确释放
**检查**:
- 确认没有在全局变量中保存大量日志条目
- 使用 Chrome DevTools Memory Profiler 检查内存泄漏

### 问题3: 测试函数未定义
**原因**: 应用未完全加载
**解决**: 刷新页面，等待加载完成后重试

### 问题4: 性能测试报错
**原因**: 日志系统初始化失败
**检查**:
- 查看控制台是否有错误消息
- 确认 logger 对象存在

## 性能优化建议

如果性能测试未通过，考虑以下优化:

1. **批量写入**: 累积多条日志后批量写入
2. **节流**: 限制日志写入频率
3. **队列管理**: 使用优先级队列管理日志
4. **Worker线程**: 将日志处理移到 Worker 线程
5. **延迟序列化**: 只在写入时序列化对象
